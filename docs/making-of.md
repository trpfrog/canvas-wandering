# 大学の Java 課題ゲームを Web 向けにリマスターした話

2020 年に大学の授業でチームで作った Java/Swing 製のゲーム **Space Wandering!!**（[trpfrog/medipro-game](https://github.com/trpfrog/medipro-game)）を、ブラウザで遊べるようにしました。

- 元: Java 約 8,400 行 + 素材 64MB、`java -jar` で起動するデスクトップアプリ
- 今: TypeScript 約 3,400 行（テスト込み）、JS 約 61KB + 素材 5MB、GitHub Pages で動く静的サイト

作業は Claude Code にほぼ任せました。お風呂に入っている間も含めて自走してもらい、途中で方針をいくつか投げ込んだ、という進め方です。この記事は、その経緯と試行錯誤のまとめです。

---

## 1. 技術選定: Rust/wasm を使いたい気持ちとの戦い

最初の希望はこうでした。

> wasm + Rust を使ってみたさあるのでそれでできたら最高かもしれません。canvas でも行けるのかなー

候補はこの 5 つです。

| 案  | 構成                                    | 所感                                                          |
| --- | --------------------------------------- | ------------------------------------------------------------- |
| A   | TypeScript + Canvas 2D + Vite           | 最軽量。`Graphics2D` の呼び出しをほぼ 1 対 1 で置き換えられる |
| B   | Rust + wasm-bindgen/web-sys + Canvas 2D | Rust をたっぷり書ける。web-sys の記述が冗長                   |
| C   | Rust + macroquad                        | ゲームエンジンらしく書ける。日本語フォントやダイアログは自作  |
| D   | Rust（ロジック）+ TS（描画・UI）        | 役割分担はきれいだが、ビルドが 2 系統                         |
| E   | Bevy / Phaser                           | この規模には重すぎる                                          |

ここから質問を重ねて詰めていきました。

**「当たり判定とか canvas で軽くかけるんだろうか」**
当たり判定は Canvas の仕事ではなく、自分で書く数学の処理です。なので言語は関係ありません。元のコードは `java.awt.geom.Area`（任意図形のブーリアン演算）を判定のたびに作り直していました。でも実際に使っている形は円と多角形だけで、全部で 100 行ほどで書けます。

**「HTML in canvas あると楽かな」**
対応ブラウザがまだ限られます。それに、ダイアログは Canvas の上に DOM を重ねれば済みます。

**「コードがシンプルになるのはどっち？」**
このゲームのコードの大半は、描画・素材読み込み・入力・UI です。どれもブラウザ API との橋渡しで、Rust だとこう書くことになります。

```rust
let cb = Closure::<dyn FnMut(KeyboardEvent)>::new(move |e: KeyboardEvent| {
    keys.borrow_mut().insert(e.code());
});
window.add_event_listener_with_callback("keydown", cb.as_ref().unchecked_ref())?;
cb.forget();
```

TS ならこれが `addEventListener("keydown", e => keys.add(e.code))` の 1 行で済みます。

**「今後拡張するならどっち？」**
ゲーム作りの本質は「作る → 遊ぶ → 直す」をどれだけ速く回すかです。HMR がある TS が有利で、Rust が明確に勝つのは性能が足りなくなったときとネイティブ版を出すときくらいです。

結論は **TS + Canvas 2D + Vite** になりました。Rust はまた別の、計算が主役の題材で触ることにします。

## 2. 方針: 「Java から移植したんだなw ってバレないくらい」

作業中に、方針が少しずつ鋭くなっていきました。

1. 「MVC にこだわる必要はなくて完全にモダンスタックで良いです。振る舞いだけ揃えたい」
2. 「バグは一緒に治しておきたい」
3. 「実装はあまり元実装に引っ張られなくて良いです。今ある最高の設計をしたい」
4. 「ファイル名のネーミングも typescript 流のもので」
5. 「Java から移植したんだなwってバレないくらいモダンな感じにしちゃって ok」

最後の一言は効きました。単なる移植ではなく、振る舞いだけを仕様として残すリマスターになったわけです。

## 3. 元のコードを読む: バグの発掘

8,400 行を読むと、締め切りに追われた課題コードらしい味わい深いバグがたくさん出てきました。代表的なものを挙げます。

- **メダルを無限に獲得できる**: メダルを `Image` インスタンスで比較していて、しかも毎回画像を読み直していました。そのため同じメダルが「未獲得」と判定され、完成した星座に触れている間は数秒おきに「You got a medal!」が出ていました
- **地球が二度と爆発しない**: Moon's Work の `Earth.exploded` が `static` でした。一度ゲームオーバーになると、以降のプレイは終わらなくなります
- **実績音が一回しか鳴らない**: `Clip` を巻き戻さずに再生していました
- **閉じるボタンが無い**: メダル画面の "I got it" ボタンを作ってはいたものの、画面に追加していませんでした
- **レースの車が止まらない**: 加速 +10 と摩擦 −8 が割り切れず、速度 0 の周りで永遠に振動していました
- **Caps Lock でレースが操作不能**: `'w'` という文字で判定していました
- **当たり判定が 1px ずれる**: `translate((int)x, (int)y)` で整数に切り捨てていました

全部直して、`docs/changes-from-original.md` に「元の挙動 → 今」の表で残しました。

## 4. 本家の未マージ PR も取り込む

> 本家に PR 来てて取り込めてないやつも全部取り込んであげたいっす　マッチョリスペクトは残しておいて

本家には、マージされないまま止まっていた PR がありました。

- **#273 マッチョ星雲**: 腕をドラッグして曲げる筋トレゲーム。ポーズすると即終了するバグを直して取り込み
- **#271 星屑集め**: 小便小僧（※星屑です）が撒く星屑をカップで受けるゲーム。ループ中に配列から要素を消していて、次の星屑が判定から漏れるバグを修正
- **#231 マッチョの AA**: コード中にマッチョのアスキーアートを置くだけの PR。`src/main.ts` の冒頭にコメントとして鎮座させ、マッチョ星雲の「ルール」画面にも同じ AA を出しました。Respect.

ちなみに AA には全角スペースが入っていて、oxlint の `no-irregular-whitespace` に怒られました。文字列とコメントの中だけ許可する設定にしています。マッチョを守るための lint 設定です。

## 5. 素材: 64MB → 5MB

`scripts/convert-assets.sh` を書いて、ビルド前の一回だけ変換するようにしました。

- WAV の BGM（38MB）→ MP3 に変換。ループ開始位置（宇宙 BGM は 1.412 秒、ミニゲーム BGM は 21.176 秒）は Web Audio の `loopStart` で再現
- PNG/GIF → WebP
- Moon's Work の爆発 GIF（134 フレーム）→ 12 列のスプライトシート 1 枚に。元は差分フレームを合成せずに描いていたので、爆発がチカチカしていました。これもついでに直りました

ImageMagick の `montage` がフォントを探しに行って落ちたので、`+append` / `-append` を行ごとに回してタイル状に並べています。

## 6. ツールチェーン: Vite+ と強めの oxlint

> vite-plus 使って欲しいのと、型に関しては oxlint で強めのルール積んで欲しいっす

[Vite+](https://viteplus.dev/) は、Vite・Vitest・Oxlint・Oxfmt を `vp` という 1 つの CLI にまとめたツールチェーンです。`vp check` を 1 回走らせれば、フォーマット・lint・型チェックが全部終わります。

導入時にはこんな詰まりどころがありました。

- **pnpm の minimumReleaseAge に引っかかる**: 公開から 1 日経っていない vite 8.3.6 を pnpm が拒否しました。lockfile を作り直し、vite-plus-core の override 経由で解決しています
- **`vite/client` の型が見つからない**: Vite+ では `vite-plus/client` を指定します
- **型を意識した lint で約 80 件のエラー**: `no-non-null-assertion`、`strict-boolean-expressions`、`no-unsafe-*`、`switch-exhaustiveness-check`、`no-floating-promises` などを有効にした結果です。`!` は `at()` やガード節に、JSON の `as` 型アサーションは型ガードに置き換えました

## 7. ブラウザで遊んで確かめる

Claude in Chrome で実際にブラウザを操作して、6 本のミニゲームをすべてゲームオーバーまで遊び、コンソールエラーが出ないことを確かめました。

面白かったのは流れ星ゲームです。スクリーンショットに流れ星がまったく写りませんでした。描画のバグを疑って Canvas のピクセルを数えてみると、ちゃんと描かれていました。流れ星は秒速 200° で画面を横切るので、スクショのタイミングではもういなかっただけです。元のゲームと同じ速さで、流れ星はちゃんと一瞬でした。

## 8. レビュー 3 連発

> いろいろ終わったら simplify と code-review, そして typescript らしさをレビューしてもらってください

### `/simplify`

再利用・簡素化・効率・作りの深さ（altitude）の 4 つの観点で、エージェントが並行してレビューしました。主な指摘と対応は次のとおりです。

- Esc でのポーズを各シーンが個別に処理していたので、シーンの `pauseMenu()` フックにまとめた
- 下に隠れたダイアログにフォーカスが残る問題を小細工で回避していたので、`inert` 属性に置き換えた（銀河鉄道で Enter を 2 回押すと 2 回回答できるバグも同時に解消）
- HUD を毎フレーム描き直していたので、背景はオフスクリーンにキャッシュして値だけ描くようにした
- ダイアログ表示中は Canvas を再描画しないようにした

### 「あれ、class って ts っぽくないと思うんだけど」

simplify の結果、ミニゲームは `abstract class MiniGameScene` を継承する形にまとまっていました。そこへ一言。

> あれ、class って ts っぽくないと思うんだけど最初から class 使ってた？

使っていました。しかも simplify で抽象基底クラスまで生えて、一番 Java っぽい形になっていたところでした。

そこで「TypeScript らしさ」を専門に見るレビューをかけました。出てきた指摘の例です。

- `class` + `abstract` + `protected` の継承階層
- `AudioManager` や `Player` のようなシングルトンクラス（`Manager` という名前自体が Java）
- `setSceneStack()` / `scenes()` という Service Locator
- `ticks % 2 === 0` のような Swing Timer 由来のティック数え
- 「as in the original」「ported from」というコメント（移植したことがバレる）
- `null` と `undefined` の混在、`rgba(0xcd, 0xcd, 0xcd, 0x75)` のような `java.awt.Color` っぽい色指定

これを受けて、全部書き換えました。ミニゲームはこうなっています。

```ts
export const macho: MiniGameEntry = {
  title: 'マッチョ星雲',
  // ...
  result: { title: 'YOUR MUSCLE', medal: { def: MEDALS.macho, minScore: 100 } /* ... */ },
  start({ end, isOver }) {
    let angle = 0;
    let drag: { startX: number; startAngle: number } | undefined;
    return {
      pointerDown: (p) => {
        drag = { startX: p.x, startAngle: angle };
      },
      update(dt) {
        /* ... */ if (remainingMs === 0) end(Math.floor(best));
      },
      render(ctx) {
        /* ... */
      },
    };
  },
};
```

- シーンは「関数が返すただのオブジェクト」になった。状態はクロージャの中
- 結果画面とメダル条件は、継承ではなく**データ**として宣言する。スコアの無いレースゲームは `result` を書かないだけで済む（以前は `super({ title: '', background: '' })` という苦しい書き方だった）
- 音とメダルは ES モジュールそのものをシングルトンにした（`import * as audio from './audio'`）
- `every(20, steer)` という小さなヘルパーで、ティック数えを「何ミリ秒ごと」という書き方に置き換えた
- `tsconfig` に `erasableSyntaxOnly` を入れて、enum や parameter properties が戻ってこないようにした

差分は +1,793 / −1,903 行です。書き換えのついでに、星座の星が順番を間違えてリセットされると 35px から 30px に縮む、という元からの小さな不整合も見つかって直りました。

### `/code-review`

最後に、最終形に対してバグ探しのレビューをかけました（途中で利用上限に当たって止まり、リセット後に再開しています）。指摘は 10 件で、元のゲームと照らし合わせて 7 件を直しました。

- **シーン入れ替えの一瞬に宇宙が「再開」していた**: トランジションが `pop()` → `push()` でシーンを差し替えていたので、その間に下の宇宙シーンが一瞬だけトップになっていました。そのたびにロケット音が鳴り出し、無敵時間が付き、星が再配置されていたわけです。シーンスタックに `replaceTop()` を足し、`popUntil()` も途中のシーンを再開しないようにしました。シーン側に特例を書くのではなく、スタックの仕組みの側で直しています
- **ミニゲームの星が重なりうる**: 格子点を選んでから最小間隔いっぱいまでずらしていたので、「500px 以上離す」という約束が守られていませんでした。しかも 6 個ちょうどしか入らない格子で、7 本目のミニゲームを足すと落ちる状態でした。ランダムに打って近すぎたら捨てる（dart throwing）方式に変え、約束どおりの間隔で 20 個ほど置けるようになりました
- **Enter 連打で宇宙の旅が消える**: 銀河鉄道の回答で Enter を押しすぎると、結果ダイアログで先頭の「Back to Main Menu」にフォーカスが当たっていて、宇宙の状態ごと捨てていました。結果ダイアログではボタンにフォーカスを当てないようにしました
- **音量スライダーが矢印キーで動かない**: ゲーム用にスペースキーと矢印キーの既定動作を止めていたのが、フォームの部品にまで効いていました
- **地球が爆発した後も点が入る**: Moon's Work で地球が爆発してから終了するまでの 3 秒間も点が入り、負けたのにメダルを取れることがありました
- そのほか、ポーズ中に指を離すとマッチョの腕が曲がり続ける問題と、BGM の後読み込みに失敗したときに何も報告されない問題

一方で「ポーズから戻るとロケットが止まって無敵になる」という指摘は、元の Java 版の `Rocket.resume()` がまさにそうしていたので、仕様として残しました。振る舞いを揃えるのが今回の約束です。

## 9. 振り返り

- **振る舞いを仕様にすると、設計は自由になる。** 元の MVC やクラス構成を捨てても、遊んだ感触（速度、判定、出現率、BGM のループ位置）を揃えれば同じゲームになる
- **言語選びは「どこにコードが多いか」で決まる。** このゲームはブラウザ API との橋渡しがほとんどなので、TS が素直だった
- **lint は設計レビューの代わりにはならない。** 強い lint を全部通しても、`abstract class` は「TS らしくない」と言われるまで残っていた。人間の一言が一番効いた
- **6 年前の課題コードは宝の山。** `static` 一個で地球が不死身になるのは、なかなか見られない

マッチョは今日も `src/main.ts` の一番上で腕を曲げています。
